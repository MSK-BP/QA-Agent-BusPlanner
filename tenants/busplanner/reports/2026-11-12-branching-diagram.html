New World Branching Model

Trunk is main and holds only QA-passed work. Each item is tested in a QA environment before it merges. A release branch is cut from main for stage, and a v* tag ships to prod. Fixes land on the release branch and merge back.

What the pipelines need for this to work

  • Build once, promote the image. Today every environment rebuilds from its branch. Stage and prod should deploy the image built from the release SHA, so prod runs what regression tested.
  • Migrations. Parked PRs and parallel branches will collide on NN_ numbers and the ordered MigrationCatalog. Use timestamp ids, run MigrationTool in each deploy (QA env resets too), and keep schema changes additive so a reverted item doesn't strand a column.
  • QA env data. Staging holds real customer data and dev config points at real BP Info. QA env backups need scrubbed data and outbound integrations off.
  • Close the gaps. FE and BE region defaults differ (US vs Canada). Service pipelines deploy any branch. PR checks skip MigrationTool, ETL and the GPS services.
