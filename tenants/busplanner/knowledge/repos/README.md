# Repo maps

One file per product repo, written by `/onboard-repo <path>`. Each map contains:

1. Purpose and owning team
2. Tech stack and how to build and run locally
3. Module map: folder, responsibility, key entry points
4. Test inventory: frameworks, suites, commands, how to run a single test
5. CI: pipeline files and what they run
6. Feature-to-code index: feature name, source paths, test paths
7. Gaps and risks noticed
8. Commit hash the map was built from, so staleness is visible
