## 3. Business rules found here and not in domain.md

Each line is a testable statement. "(open)" = desired behaviour stated in an unfixed ticket, not shipped behaviour.

### Workflow (BP Web forms)
- A form with Submission Uniqueness enabled refuses a second submission for the same student while one is active (Submitted / In Review / Pending); it accepts again once that one is Approved / Rejected / Cancelled. (ENG-265, ENG-220)
- Uniqueness is keyed on Parent + Student + Form; the same parent can submit immediately for a different student. (ENG-265)
- Uniqueness is a per-form setting, default OFF, changeable without deployment; the saved Conflict behavior reloads as saved (`wf_FormSubmissionPolicy.ConflictBehavior`). (ENG-265, ENG-221)
- Conflict behaviours: Block only (0) = neutral message, no link; Block + view (3) = link to existing + Return; Block + view + delete (1) = link, Keep, and red "Delete it and submit this new request" which deletes the open submittal and submits the new one; Warn only (2) = submission goes through. (ENG-221)
- Known gap: Warn only renders the warning then submits immediately, so the parent never sees it. (ENG-221)
- The existing-submission link and Keep/Delete buttons show only to the owner (logged-in subscriber whose email matches the submitter) or staff; everyone else sees only the neutral message, and block modes still block. (ENG-221)
- A form with no matching student-id control (or blank at submit) ignores the policy and submits normally; default control id is `tbStudentNumber`, model-based forms use `ucStudentInfo_tbStudentID`, and FormAdmin fills the right one on load/save without overwriting a typed id. (ENG-221)
- Forms sharing a non-empty Uniqueness Group Key are mutually exclusive: an active submission on form B blocks form A for that student. (ENG-221)
- Appending `&ModelId=<guid>` to a `?SubmittalId=` link must not bypass the permission check; preview is `ModelId` without `SubmittalId` only. (ENG-221)
- The existing-submission link must include the `/Workflow` sub-path (no 404). (ENG-221)
- A blocked submit scrolls the page to the top so the message is visible. (ENG-221)
- With `Workflow_AttachSubmittalPdfToConfirmationLetter` ON (default OFF), the submit-time confirmation letter carries a PDF of the submitted form with the entered values; with it OFF there is no attachment; a PDF failure still sends the letter. (ENG-248)
- Workflow letters cannot merge field values into the body; only the student name is added, to the subject line. (ENG-248)
- A form whose Assign Type is Manual renders an "Assign to" panel (NestedForm.master); this is setup, not a defect. (ENG-258)
- Workflow emails with several attachments selected must send all of them (open). (ENG-198)
- DistrictAdmin must see the same students in STR form Student Search as Admin for its district (open). (ENG-347)
