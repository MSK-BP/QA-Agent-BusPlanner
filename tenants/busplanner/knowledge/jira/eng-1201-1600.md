## 3. Business rules found here and not in domain.md

Testable one-liners. "(bug)" means the rule is the expected behaviour stated in an open or fixed bug.

### GPS+ (New World)
- Device Mapping: exactly one active mapping per vehicle and per device; saving a conflicting pairing auto-retires the old mapping at new effective date minus 1 day, and the retired row shows in History (ENG-1203).
- Device Mapping: Save writes all staged pairings in one transaction; Cancel writes nothing; needs `dev:mapping:write` (ENG-1203, ENG-1211).
- Device Mapping: Auto-map by Name stages only unambiguous 1:1 case-insensitive, trimmed name matches; names matching 0 or 2+ counterparts stay unmapped (ENG-1206).
- Device Mapping: retire-now sets retire = today; a future retire date keeps the mapping Active until then; freed device and vehicle return to the unmapped queues (ENG-1204).
- Device Mapping: unmapped lists exclude anything actively mapped or staged, and the count chip equals the list length (ENG-1202, ENG-1209).
- Historical GPS+ pages (Event Viewer, Path & Stop Compare, their selectors) resolve the plan snapshot by date, never by `is_active`, which marks a ~10-day forward window (ENG-1287, ENG-1289).
- Event Viewer: Ignition is one session; on-samples less than 15 minutes apart merge (fixed constant, not a setting); Red Lights is not shown (no data column) (ENG-1286).
- Event Viewer: event Location is blank in V1 (no reverse geocoding); stops are not drawn on its map (ENG-1249, ENG-1318, ENG-1319).
- Event Viewer export is built in the browser and must guard against spreadsheet formula injection (ENG-1291).
- Path & Stop Compare filter: one request returns every route for the date with its runs nested; routes with no bus are returned and flagged, not left out (ENG-1335).
- Path & Stop Compare: a stop's map pin and its grid row always show the same outcome (ENG-1336).
- Path & Stop Compare: on-path compliance covers only the displayed date (ENG-1336).
- Path & Stop Compare V1 outcomes are derived at read time from the stored evidence level; courtesy (unplanned) stops and true arrival/departure times are out of V1 (ENG-1248, ENG-1320, ENG-1322).
- Customer time zone is stored as a Windows time-zone ID; an IANA ID sent to the customer API is converted on write (ENG-1282, ENG-1351).
- Live Viewer "Show on map" plots the current grid page, the pinned buses, or both (ENG-1595).
- The GPS+ substitution import (BP Info route-to-vehicle) is idempotent, skips and logs unmatched IDs, reverts its own overlay when the mapping is retired, and one failing tenant does not stop the others (ENG-1239, ENG-1241, ENG-1242, ENG-1243).

### Time & Attendance (New World)
- All T&A timestamps are stored in UTC and shown in the tenant's time zone (INV-1); changing the district time zone changes displayed times only, never worked hours, payable or OT (ENG-1348, ENG-1560 bug).
- Multi-punch payable equals the sum of the punch windows, not the span from first in to last out (ENG-1350 bug).
- Every material change, including deleting a shift, emits an audit event naming the actor (INV-7) (ENG-1357 bug).
- In a Closed or Exported pay period, edits are refused by the server and the UI must show a frozen notice instead of offering Save (INV-11) (ENG-1358 bug).
- Edit-time validation errors return 400 and frozen-period edits 409; a 500 on save is always a defect (ENG-1397).
- An unresolved shift in an earlier week must not block new clock-ins (ENG-1388 bug).
- Overlapping punches are rejected even across different or missing job codes, and a card with overlaps cannot be approved (ENG-1589 bug).
- Revoking a delete permission hides Delete and the server refuses the delete (ENG-1597 bug; rule already in domain.md, this adds that the server does not enforce it).
- Nash PDF: one driver per portrait page; per-week Total/Reg/OT plus only the absence codes that occurred; a week with no hours is greyed (ENG-1524).
- Time Card filters: two values in one filter give the union; Positions and Departments combine with AND; inactive values list last marked "inactive"; filters reset on reload (ENG-1526, ENG-1527).
- Time Card dates: Work week mode on every load; Custom range up to 6 weeks; the arrows never switch mode (ENG-1529).
- Time Card CSV (Synovia/LINQ scan file): 5 columns, no header, one row per punch: I/O, employee number, job code short name, yyyymmdd, hhmmss without leading zeros, in district local time; edited punches export the corrected time (ENG-1530, ENG-1534).
- Payroll Export Custom range ignores pay-period locking, freezes nothing and can be rerun; with no pay periods configured, Step 1 opens on Custom range (ENG-1532).
- A Positions/Departments-filtered payroll export does not mark the pay period Exported; exported days become locked on the Time Card (ENG-1533).
- A client sees only the export formats configured for it (ta_settings key); others are hidden (ENG-1535).

### Ridership reports (BP Web + BP Quick, 13.4.0)

- `Reports_RidershipStopMatchToleranceMetres` defaults to 0 (off); beyond the tolerance, Matched Stop reads "Not determined"; way points and turn-around points are never matched (ENG-1392).
- Flags are evaluated top-down, first match wins: Did not ride, Left on vehicle, Boarded wrong bus, On at wrong stop, Off at wrong stop (ENG-1393, ENG-1471).
- Left on vehicle = a boarding with no alighting for that student that day; it is suppressed when the run recorded no alighting from anyone that day (ENG-1394).
- Did not ride is informational: it is excluded from incident totals and from "Flagged rides only" (ENG-1395, ENG-1473).
- Historical searches use the roster, stop list and card mapping as of the scan date, and say how many students have since been removed (ENG-1573).

- `Enable_Ridership_VehicleAnalytics` (Quick setting 63, default off) hides Vehicle Performance and Vehicle Occupancy; their URLs redirect to Ridership Reports; dashboard tiles for them are hidden, not disabled (ENG-1365, ENG-1366, ENG-1483).

- Quick ridership filters are three alternative search modes (Route/Run, Student, School); date, time and scan type modify the active mode; filter values persist when switching reports (ENG-1409).
- Ridership states are shown with colour and a text label (Tap green, Manual blue, No scan red, N/A) (ENG-1422).
- The Quick matrix shows at most 7 day columns and directs longer ranges to export; first page in under 30 s, School mode under 30 s (ENG-1421, ENG-1430, ENG-1466).
- Scan Usage card statuses: No card issued, Reissue candidate, Card reappeared - hold reissue, Occasional - monitor, with a configurable detection window (ENG-1432).
